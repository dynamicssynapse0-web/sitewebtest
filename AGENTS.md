# AGENTS.md

## Layout & entrypoints
- Next.js 16 App Router, plain JavaScript; `jsconfig.json` maps `@/*` to `src/*`. App code is in `src/app`, components in `src/components`, data helpers in `src/lib`.
- There is no top-level `components/` directory anymore; all components live in `src/components` and imports resolve `@/components` to `src/components`.
- `README.md` is the untouched create-next-app template (points at `app/page.js` and Geist). The real layout uses `Inter` from `next/font/google`. Trust source/config over README.

## Commands
- Scripts are only `npm run dev`, `npm run build`, `npm start`, `npm run lint`. No test/codegen/pre-commit/CI setup; TypeScript is checked inside `next build`, so verify with `npm run build` (plus `npm run lint`).
- `npm run lint` runs bare `eslint` using the flat config in `eslint.config.mjs` (next/core-web-vitals). It should exit 0 with no errors and no warnings.
- `next.config.mjs` enables `reactCompiler: true`, pins `turbopack.root` to the repo root, registers `@tailwindcss/turbopack` for `*.css`, sets `poweredByHeader: false`, and allows remote `next/image` sources from `loqsvylndmyfntuaecxd.supabase.co` (`/storage/v1/object/public/**`). Don't remove the CSS loader rule. It also exports a global `headers()` with `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` and `Strict-Transport-Security`.

## Content model (Supabase only)
- Public content comes **only** from Supabase tables `articles`, `images_sport`, `categories_sport`, `sportifs_semaine` and `vitrine_items`. Legacy files under `content/` and local photo folders under `public/images/sportifs-semaine/` are **no longer read or merged**; they may remain as unused archives. The formerly broken `content/events/guinness-super-league.md` has a complete YAML block but is ignored by the app.
- `src/lib/events.js` and `src/lib/internationalCompetitions.js` export async helpers (`getAllEvents`, `getEventBySlug`, `getAllInternationalCompetitions`, `getInternationalCompetitionBySlug`) backed by `getRemoteArticles('event')` / `getRemoteArticles('international')`. All callers must `await` them. `mapArticle()` exposes `eventTitle` (aliases `event_title`, `titre_evenement`, `eventTitle`, then legacy `competition`) so the admin label « Titre de l’événement » works without a new database column. `internationalCompetitionSlug(title, eventTitle)` builds distinct public URLs when several competitions share the same `title`; editing an existing row keeps its published slug. The same uniqueness rule is applied to every admin form with a public detail URL (see Admin section below).
- `src/lib/sportifsSemaine.js` exports async `getAllSportifs()` / `getSportifById()` backed by `sportifs_semaine` only. There is no static `portraits` export and no `fs` folder scan; `/sportifs-semaine/[id]` has no build-time static params.
- `src/lib/vitrine.js` exposes `getMomentsForts()` (`vitrine_items.section = 'moment_fort'`) and `getPortraitsExclusifs()` (`section = 'portrait_exclusif'`), ordered by `ordre`. `src/components/ExclusivePortraits.js` receives them via `items` and renders an empty state when there is none.
- `src/lib/imagesSport.js` exports async `getImagesSportDisciplines()` / `getImagesSportBySlug()` backed by `images_sport` only. Each mapped discipline has `coverImage`, `secondaryImages` and a deduped full `images` gallery (cover first). `src/lib/sports.js` still exports the static `listeSports`, plus `mergeSports()`, async `getAllSports()` and `getSportBySlug()`: `images_sport` rows override base sports by `slug`, so publishing `BASKETBALL` or `BOXE` automatically feeds `/sports`, `/sports/[slug]`, the sitemap and `/galerie`. `getAllSports()` also merges `categories_sport` under the discipline slug, so each sport carries `categories`, a discipline cover when needed and a deduped `imageCount` including all sub-discipline photos.
- `src/lib/gallery.js` → `getGalleryImages()` aggregates the six Supabase-backed collections (including `images_sport`). `/galerie` renders « Aucune photo pour le moment. » when empty.
- `src/lib/categoriesSport.js` uses the exported `fetchRows()` / `parseImagesField()` from `src/lib/supabase/content.js` to read `categories_sport`. `parseImagesField()` repeatedly decodes JSON strings (up to 6 passes) so legacy double-encoded `images` values still normalize to an array. Only six canonical disciplines are allowed: Football, Basketball, Boxe, Volleyball, Athlétisme, Arts martiaux. Each row has a required `cover_image`, at most 4 secondary `images`, and a unique composite slug `slugify(discipline-sous_discipline)`. `getActiveSportDisciplines()` groups rows by discipline and powers the two-level Navbar; `getCategorySportBySlug()` accepts either the discipline-scoped slug or the composite slug. The table SQL is in `sql/categories_sport.sql`.
- `src/lib/supabase/records.js` normalizes images (`src/url/path`, `alt`, `legend`, `credit`), decodes JSON columns, slugifies titles and sorts/dedupes collections. `src/lib/supabase/content.js` → `mapArticle()` accepts `title`/`titre`, `cover_image`/`image`/`image_url`, `images`/`photos`/`image_urls`, and `lieu`/`resume`/`description` aliases.
- Dates: `date: "YYYY-MM-DD"` (Supabase text/date) renders as a long French date; without it use `season` (`Saison ...`) or get « Date à confirmer ». Preserve the non-ASCII filename `aubinèsimo-lions.jpg` verbatim wherever it is still referenced.
- Public data pages set `revalidate = 60`; admin writes call `revalidatePath('/', 'layout')` plus every public route (and the affected detail slug) from `src/app/admin/actions.js`, and the admin UI calls `router.refresh()`. `sitemap.ts` is async and lists every Supabase slug, including merged sport slugs. `/admin` is `noindex` via layout metadata and disallowed in `robots.ts`.
- Empty or « Sans titre » `articles` rows and rows whose `type` doesn't match are dropped by `isValidArticleRow()` in `supabase/content.js`, the per-type filters in `events.js` / `internationalCompetitions.js`, and `isArticleOfType()` in `/admin/page.js`. Every public listing and home section has a clean French empty state.

## Admin (Supabase)
- `.env.local` (gitignored) must define `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`; the checked-in file contains a placeholder key and must be replaced with the real publishable key, then the server restarted.
- `src/lib/supabase/{config,client,publicClient,server,admin,content,records}.js` hold the SSR/browser/public clients and mappers. `isSupabaseConfigured` rejects placeholder/short keys so the public site still renders clean empty states when Supabase isn't set up.
- `/admin/login` signs in with `supabase.auth.signInWithPassword`; `/admin/page.js` then requires a profile with `role: admin` and `statut: actif`. Profile lookup tries configured tables then `utilisateurs`, `users`, `profiles`, `user_profiles`, `admin_users`, matching `id`/`auth_user_id`/`user_id`/`uid` or `email`/`user_email`/`mail`. Unauthorized users get an "Accès refusé" screen, not the dashboard.
- `/admin` is mobile-first: 7 large rubric buttons → dedicated form + published list with edit/delete. Sections: **Grandes compétitions** (international competitions, `articles` with `type = international`), events (`articles`), **Images Sport (`images_sport`)**, **Catégories de sport (`categories_sport`)**, sportifs de la semaine (`sportifs_semaine`), moments forts and portrait exclusif (`vitrine_items`). `/admin/page.js` loads **only Supabase rows** and passes them directly to `AdminDashboard.js`. Every one of the 7 forms has a « Choisir un élément existant… » selector with « + Créer un nouveau titre »; selecting a published Supabase row prefills all fields (title, sport, location, date, competition, photos, etc.) so photos can be added or the row modified without retyping the title. The Images Sport selector also offers the base sports from `listeSports` (Football, Basketball, Athlétisme, Boxe) with their title/description/cover prefilled; published rows with the same slug take precedence. The Catégories de sport selector labels rows `Discipline — Sous-discipline`. Saves/deletes call `router.refresh()` in addition to the server-side `revalidatePath()`.
- Files are uploaded directly from the browser to Supabase Storage bucket **`media`** as `<section>/aubin-simo-bilderfassung-<slug du titre>-<timestamp ms>-<index>-<random>.<ext>`. `buildUniqueUploadName()` in `src/lib/upload.js` combines `Date.now()`, the file index and a `crypto.randomUUID()` suffix so parallel uploads never collide; the impure calls stay outside React render scope. It accepts an optional `tag` (ex. `cover`), producing `aubin-simo-bilderfassung-<slug>-cover-<timestamp>-<index>-<random>.<ext>` for Images Sport, Catégories de sport and Grandes compétitions covers. Every `.upload()` call uses `{ upsert: true, contentType: file.type }`. An empty alt field falls back to `Aubin Simo - Bilderfassung <titre>`; credit is always `Aubin Simo`. Vitrine rows store the public URL in both `image` and `image_url`, plus `alt`.
- All writes go through `src/app/admin/actions.js` server actions (`'use server'`), which re-check admin authorization and whitelist the five tables (`articles`, `images_sport`, `categories_sport`, `sportifs_semaine`, `vitrine_items`) before insert/update/delete. A discreet `Admin` link sits in the footer.
- `saveInternationalCompetition()` / `deleteInternationalCompetition()` wrap the `articles` table for the « Grandes compétitions » rubric. The form stores **Titre** in `title`, **Titre de l’événement** in the existing `competition` column, a mandatory separate `cover_image` and at most **4** secondary `images`; `handleFiles()` and the server action both reject larger selections. New rows get a slug from `title + competition`, so two « CAN 2017 » entries with different events remain distinct; updates keep the existing slug and the admin selector labels rows `Titre — Titre de l’événement`. Choosing « + Créer un nouveau titre » (also right after a save) keeps only the main **Titre** and clears the event title, cover and photos, so another event can be published under the same title. Inputs have no `name` attribute and the form uses `autoComplete="off"` to stop browser autofill from restoring the previous event title. The shared selector uses the explicit `NEW_ITEM_KEY = '__new__'` value (the option carries the same value) so switching back to creation always fires `onChange` and never keeps showing the previously selected row; a dedicated reset button is available in every rubrique. `keptIdentity()`/`resetToNew()` generalize this: Grandes compétitions, Événements and Sportifs keep their **Titre**, Catégories keep their **Discipline**, while Images Sport and vitrine clear everything; the distinctive field (event, date/lieu, joueur, sous-discipline), cover and photos are always emptied. Missing/stale rows after a refresh and deletion of the row currently being edited also reset the form instead of leaving old values on screen.
- **Slug uniqueness across all 7 forms:** `saveItem()` in `actions.js` now runs `uniqueSlug()` before every insert/update — it reads the table's existing slugs (excluding the row being edited), keeps the slug already published on updates, and appends `-2`, `-3`… if the desired slug is taken. On creation, the desired slug is composed from the title plus a distinguishing field: `title + competition` for Grandes compétitions, `title + date + lieu + saison` for Événements (`saveEvent`), `title + player_name` for Sportifs (`saveSportif`), `images_sport` title, and `discipline-sous_discipline` for Catégories. The admin selectors show those distinguishing values (`Titre — Événement`, `Titre — date · lieu`, `Titre — Nom du joueur`, `Discipline — Sous-discipline`, published slug for Images Sport) so two rows with the same title can be told apart. Vitrine rows (moments forts / portrait exclusif) have no public detail URL; duplicated titles there are intentional because `groupVitrineItems()` merges their photos, but their DB slugs are still unique. `/sportifs-semaine/[id]` also displays `nom — poste`.
- Every exported action catches its own errors and returns `{ ok: true, data }` / `{ ok: true, id, removedMedia }` or `{ ok: false, error }` — never throws, so a failed query can't surface as a production RSC error (#441). `AdminDashboard.js` checks `result.ok` before updating its local state.
- `src/lib/supabase/serialization.js` → `toPlainJson()` / `toPlainRows()` / `safeText()` strips `Date`, class instances, `undefined`, functions and circular refs. All Supabase reads in `/admin` are wrapped in `try/catch` and sanitized before crossing to the client, so a missing table/column renders an empty rubric instead of crashing.

## Médias & performances
- Before upload, `src/lib/imageCompression.js` → `compressImageForUpload()` validates the source file then resizes it client-side with a Canvas to a max width of **1600 px** (ratio preserved) and encodes it as **WebP quality 0.82**, falling back to JPEG when WebP isn't supported. The SEO filename `aubin-simo-bilderfassung-<slug>-<timestamp>-<index>-<random>.<ext>` uses the compressed blob's extension (`webp`/`jpg`), not the original one.
- `src/lib/upload.js` is the single validation authority: `validateUploadFile()` only allows `image/jpeg`, `image/png`, `image/webp` with matching `.jpg/.jpeg/.png/.webp` extensions, rejects anything else (HTML/SVG/JS/EXE/GIF/AVIF) and enforces **15 Mo before compression / 3 Mo after compression**. `AdminDashboard.js` filters files in `handleFiles()` and `compressImageForUpload()` throws on any invalid or over-limit file. `uploadFileBase()` slugifies the title without accents/spaces; `buildUniqueUploadName()` appends a millisecond `Date.now()`, the file index and a `crypto.randomUUID()` suffix. No `Date.now()`/`Math.random()` call occurs in React render scope.
- Deleting a row in `/admin` removes its images from the `media` bucket **after** the database delete, via `removeUnusedMedia()` in `actions.js`. Sources are collected from `images`, `image`, `image_url`, `cover_image`, `photos`, `image_urls`; public URLs are converted back to relative storage paths. Images still referenced by another allowed table are kept. Storage errors never block or roll back the content deletion.
- Galleries are paginated client-side in chunks of **18**: `src/components/GalerieGrid.js` (used by `/galerie`, with a counter and « Charger plus de photos (n) » button) and `src/components/Gallery.js` (event/competition lightbox grids). Only the visible slice renders `next/image` elements; the lightbox still receives the full slide list.

## Sportifs de la semaine
- Photos come only from the Supabase row's normalized `images` array. The first image is the cover; rows without a usable image fall back to `DEFAULT_OG_IMAGE`. There is no `fs` read of `public/images/sportifs-semaine/`.
- `src/components/SportifsDeLaSemaine.js` is a client component fed by `getAllSportifs()`. Below `md`: scroll-snap carousel, swipe hint and dynamic pagination. From `md`: grid; at `lg` the featured card spans 7 columns and the two secondary cards stack vertically in the remaining 5 columns via an inner `lg:grid lg:grid-cols-1` wrapper. Cards link to `/sportifs-semaine/[id]`, show badge + photo count and `nom - poste - competition`; CTA links to `/galerie`.

## Images Sport & sports
- `images_sport` rows hold **only** `id`, `title`, `slug`, `description`, `cover_image`, `images` (JSON array of secondary photos) and `ordre`. There is **no `alt` column**: never send or query `row.alt` for this table. `mapImagesSport()` generates `alt: "Photo <title>"` from the title on the front-end; any alt/legend stored inside the `images` JSON column is unrelated to a database column. The admin form has a separate cover upload (`tag: 'cover'` in the SEO filename) and a multiple secondary upload; both are compressed and stored in `media`.
- `src/components/ImagesSportSection.js` is a client component fed by `getImagesSportDisciplines()` on the home page. Cards show the cover, title, secondary-photo count and a « Voir les images » button that opens a `yet-another-react-lightbox` viewer (Counter, previous/next, Esc, arrows, touch swipe) with cover + secondary photos, plus a link to `/sports/[slug]`.
- `/sports` and `/sports/[slug]` await `getAllSports()` / `getSportBySlug()` so published disciplines override base sports by slug. `/sports/[slug]` shows the discipline's full gallery (via `Gallery`) and its linked events; empty states are in French.

## Catégories sportives & navigation
- The async root layout awaits both `getActiveSportDisciplines()` and `getAllInternationalCompetitions()` and passes them as `sportsMenu` / `competitionsMenu` to the global `Navbar`, so both dropdowns are available on every page (not only the home page). `Navbar.js` shows only disciplines that have at least one published sous-discipline: hover/click opens the desktop menu and a `+` accordion opens each discipline; mobile uses a nested accordion. The fixed `CAN 2027` tab was replaced by the `Compétitions internationales` label in `src/lib/navigation.js`; its desktop dropdown lists every published competition title and links to `/competitions-internationales/[slug]`, with a mobile accordion.
- `/sports/[discipline]/[slug]/page.js` shows the fil d’Ariane, the sous-discipline title, the full-width cover banner and the complete `Gallery` (cover + up to 4 secondary photos) using the shared lightbox. The global `ImageProtection` modal and the WhatsApp CTA `676 97 88 78` handle image orders.
- The admin form accepts exactly one cover and at most 4 secondary images. `handleFiles()` blocks a selection exceeding 4 with a French alert; `saveCategorySport()` re-checks the count server-side and rejects unknown disciplines, missing sous-discipline or missing cover. Deletion reuses `removeUnusedMedia()`.
- `/competitions-internationales/[slug]` displays the competition title, the event title, the cover banner and the shared `Gallery` in `grid` variant (each thumbnail has `aspect-[4/3]`). The global `ImageProtection` modal and a WhatsApp `676 97 88 78` order CTA are available on the detail page.
